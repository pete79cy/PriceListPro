## ✅ Likely Cause

When rendering a **delivery note PDF**, the backend usually:

1. Fetches the `Order` and its `OrderItems`
2. Loads a Jinja2 template (like `orders/delivery_note.html`)
3. Renders it with WeasyPrint or another PDF library

If something goes wrong in **step 1–3**, you get a 500 error.

## 🧩 Common Issues & Fixes

### ❌ A. **Missing Template**

```
TemplateNotFound: orders/delivery_note.html
```

✅ Fix:
Make sure this file exists:

```
templates/orders/delivery_note.html
```

And it starts with:

```jinja
{% extends "layout.html" %}
```

---

### ❌ B. **Missing Relationship in OrderItem**

Error like:

```
AttributeError: 'NoneType' object has no attribute 'plant'
```

✅ Fix:
Your template uses `item.plant.name` but the `plant` is missing or null. Add a safe check:

```jinja
{{ item.plant.name if item.plant else "Unknown Plant" }}
```

---

### ❌ C. **No items in order / order not found**

Error like:

```
AttributeError: 'NoneType' object has no attribute 'items'
```

✅ Fix:
Add this in your route before rendering:

```python
order = Order.query.get(order_id)
if not order:
    return "Order not found", 404
```

Also: Check if `order.items` is empty or null — add placeholder handling in the template.

---
