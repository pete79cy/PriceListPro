## Quick, no-risk hot-fix (gets you past the 500 right now)

Replace the whole “find last order of the year” block with **one atomic insert-retry loop**.
PostgreSQL will be responsible for uniqueness instead of our Python:

```python
def generate_order_number():
    """Atomic, race-safe order number generator: ORD-YYYY-NNN"""
    year          = datetime.utcnow().year
    prefix        = f"ORD-{year}-"
    next_seq_num  = 1

    while True:
        candidate = f"{prefix}{next_seq_num:03d}"
        try:
            db.session.execute(
                db.insert(Order).values(order_number=candidate)  # just the col that’s UNIQUE
            )
            db.session.flush()    # ← if flush works, number is ours
            return candidate
        except IntegrityError:
            db.session.rollback()  # someone grabbed that number; try next
            next_seq_num += 1
```

**What changed**

1. We rely on the **UNIQUE constraint** already on `orders.order_number`.
2. We let the DB throw an `IntegrityError` if another request just took the same number.
3. No `FOR UPDATE`, no aggregates, no race.

*(If you don’t want the throw-away insert, use a dedicated `order_numbers` sequence table or a PG `GENERATED BY DEFAULT AS IDENTITY` column and concatenate the year when you display.)*
