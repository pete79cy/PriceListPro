Below is a fresh, *task-first* redesign of the **Customers** module that fixes the two big frictions you’re feeling:

1. **Cognitive overload up-front** – too many buttons/labels before the user even sees data.
2. **Poor scanning & action flow** – hard to pick a customer, harder to act on many.

---

## A. 30-second wireframe (hi-level)

```
┌────────────────────────── GLOBAL NAV (unchanged) ──────────────────────────┐

┌── Sub-header ───────────────────────────────────────────────────────────────┐
│  Customers (34)     |   🔍 Search (⌘ K)                |  ＋ New ▼          │
└─────────────────────────────────────────────────────────────────────────────┘

┌── Main grid ────────────────────────────────────────────────────────────────┐
│  ▓  Left rail (filters)  ▓│   Customer table (sticky header, virtual)      │
│  ▓  – All ▢34            ▓│   ┌───┬────────────┬─────┬────┬───┐            │
│  ▓  – Missing email ▢28  ▓│   │ ☐ │ Name       │ …   │ ⋮ │   │            │
│  ▓  – Category chips     ▓│   └───┴────────────┴─────┴────┴───┘            │
└─────────────────────────────────────────────────────────────────────────────┘

(sticky) Bulk-toolbar appears only when rows selected
┌──────── Export | Email | Delete (n) ───────────┐
```

### Why this feels friendlier

| Principle                                 | How implemented                                                                   |
| ----------------------------------------- | --------------------------------------------------------------------------------- |
| **One “action bar” not three.**           | Search + New stay in a single sub-header; everything else moves near its context. |
| **Filters close to data, not above it.**  | Collapsible left rail; fits desktop, collapses to chips row on mobile.            |
| **Bulk actions appear only when needed.** | Slide-down toolbar with count; disappears on *Esc* or when 0 selected.            |
| **Row density tuned for readability.**    | 48 px row height, 14 px/500 font; zebra hover, dashed column guides.              |

## B. Component-by-component spec

### 1. Sub-header (48 px)

```html
<div class="flex items-center justify-between gap-4 bg-surface rounded-md p-3 mb-4">
  <h1 class="text-xl font-semibold flex items-center gap-1">
    Customers <span class="pill">34</span>
  </h1>

  <div class="flex items-center gap-3 flex-1">
    <input type="search" placeholder="Search…" class="flex-1 input-dark" />
    <button class="btn-primary">＋ New</button>
  </div>
</div>
```

*Tokens*
`pill` = rounded-full bg-blue-600 px-2 text-xs.
`input-dark` = rounded bg-layer-2 px-3 py-1.5 text-sm w-full md\:w-64.
`btn-primary` inherits 8 px radius from dashboard.

### 2. Filter rail

```html
<aside class="hidden lg:block w-56 flex-none space-y-4">

    <h2 class="text-xs tracking-wide text-gray-400">Filters</h2>

  <!-- categories -->
  <div class="card p-4 flex flex-wrap gap-2">
    <button class="filter-chip">General 12</button>
    <button class="filter-chip">Gardeners A 1</button>

  </div>

`filter-chip` = inline-flex items-center gap-1 rounded-full bg-layer-2 px-3 py-1 text-xs hover\:bg-layer-3 transition.

*Mobile*: rail collapses → chip row just under sub-header (horizontal scroll, overscroll-contain).

        <tr class="border-t border-layer-3 hover:bg-layer-3">
          <td class="px-4"><input type="checkbox"></td>

          </td>
        </tr>
        {% endfor %}
      </tbody>

  <Pagination :meta="meta"/>

```

*Styling tokens* – adopt the ones you created for cards on dashboard (`bg-[#2b2e33]` etc.) so the page feels native.

**Virtual scroll** (optional, if >1 k rows) → wrap tbody with `overflow-y-auto h-[calc(100vh-250px)]` and use `react-window`.

### 4. Row action popover (`KebabMenu`)

*Use shadcn `DropdownMenu`* to avoid the grey outline effect:

```jsx
<DropdownMenu>
  <DropdownMenuTrigger asChild>
    <button className="kebab" aria-label="Row actions">
      <MoreVerticalIcon size={16}/>
    </button>
  </DropdownMenuTrigger>
  <DropdownMenuContent side="left" align="end" className="w-32">
    <DropdownMenuItem onSelect={()=>edit(id)}>
      <Edit2Icon className="mr-2" size={14}/> Edit
    </DropdownMenuItem>
    <DropdownMenuItem className="text-red-400" onSelect={()=>del(id)}>
      <Trash2Icon className="mr-2" size={14}/> Delete
    </DropdownMenuItem>
  </DropdownMenuContent>
</DropdownMenu>
```

### 5. Bulk toolbar (slide-down)

```html
<transition name="slide-down">
  <div v-if="selected.length"
       class="fixed inset-x-0 top-[60px] z-30 flex items-center gap-4
              bg-black/40 backdrop-blur-sm px-6 py-2">
      <span class="text-sm">{{ selected.length }} selected</span>
      <button class="btn-outline" @click="exportCsv">Export</button>
      <button class="btn-outline" @click="email">Email</button>
      <button class="btn-outline text-red-400" @click="delMany">Delete</button>
      <button class="ml-auto text-gray-400 hover:text-white" @click="clear">✕</button>
  </div>
</transition>
```

CSS:

```css
.slide-down-enter-active, .slide-down-leave-active {
  transition: transform .2s ease, opacity .2s ease;
}
.slide-down-enter-from, .slide-down-leave-to {
  transform: translateY(-100%);
  opacity: 0;
}
```

## C. Implementation order (1-day sprint)

1. **Refactor HTML structure** – paste sub-header, flex grid (rail + table), move legacy buttons inside new structure.
2. **Drop in base tokens** (card, pill, chip, layer-colors) once in global CSS.
3. Remove all outline/border styles from old buttons; rely on bg hover states.
4. **Bulk toolbar logic** – reuse the existing “selected” array & actions you already have; just mount the new component.
5. Responsive QA (375 px / 768 px / 1280 px).
6. User-test: 3 tasks – search, mass-delete, filter by “Missing email”. Should be ≤ 5 s each.
