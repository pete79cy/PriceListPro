# PriceListPro — Action Plan & Proposed Changes (Cyprus VAT: 19% standard, 5% reduced)

This document is a **step-by-step implementation plan** to stabilize PriceListPro and make it correct, maintainable, and audit-friendly — with **Cyprus VAT defaults**:
- **19% (standard)**
- **5% (reduced)**

It includes:
- P0/P1 bug fixes
- VAT policy + data model changes
- money precision fixes (remove floats)
- migration plan (Flask-Migrate/Alembic)
- security hardening (API token + CSRF)
- UI consolidation guidance
- testing checklist

---

## 0) Goals (non-negotiables)

1. **Totals must be deterministic**  
   Totals must be calculated by the app (not AI), always reproducible from stored numbers.

2. **Money must not use float**  
   Store money as `Numeric(12,2)` (or integer cents). Use Decimal in calculations.

3. **VAT must follow Cyprus defaults**  
   Default VAT selection: **19%**, with option for **5%** per line item (and optionally 0% if needed later).

4. **Status values must be consistent**  
   No `.value` calls on plain string fields.

---

## 2) VAT Design (Cyprus)

### 2.1 VAT rates

Define canonical VAT options (basis points are safest, but percentage is ok):

* Standard: **19%**
* Reduced: **5%**
* (Optional) Zero: **0%**

### 2.2 Default behavior

* When creating a new product price or invoice line: default VAT = **19**
* Allow user to pick **5** if that product qualifies
* Store the chosen VAT rate on the **line item**, not just order-level

Why line-level? Because real invoices often mix VAT rates.

## 3) Proposed Model Changes (SQLAlchemy)

### 3.1 Money column standard

Use:

* `db.Numeric(12, 2)` for amounts
* `Decimal` for calculations

Create a helper for rounding:

```python
from decimal import Decimal, ROUND_HALF_UP

TWOPLACES = Decimal("0.01")

def money(value) -> Decimal:
    if value is None:
        return Decimal("0.00")
    if not isinstance(value, Decimal):
        value = Decimal(str(value))
    return value.quantize(TWOPLACES, rounding=ROUND_HALF_UP)
```

---

### 3.2 VAT rate on line items

In `OrderItem` (and similarly `InvoiceItem`, `QuotationItem` if applicable):

```python
vat_rate = db.Column(db.Integer, nullable=False, default=19)  # allowed: 19, 5 (optionally 0)
```

Validation: enforce allowed values in app layer (forms) and optionally DB CHECK constraint (if your DB supports it cleanly).

---

### 3.3 Remove duplicate Order properties (keep one set only)

In `models.py` → `Order`:

```python
from decimal import Decimal

@property
def subtotal(self):
    return money(sum((item.net_total for item in self.items), Decimal("0.00")))

@property
def vat_amount(self):
    return money(sum((item.vat_amount for item in self.items), Decimal("0.00")))

@property
def total(self):
    return money(self.subtotal + self.vat_amount)
```

And in `OrderItem`:

```python
@property
def unit_price_dec(self):
    return money(self.unit_price)

@property
def quantity_dec(self):
    return Decimal(str(self.quantity or 0))

@property
def net_total(self):
    return money(self.unit_price_dec * self.quantity_dec)

@property
def vat_amount(self):
    rate = Decimal(str(self.vat_rate)) / Decimal("100")
    return money(self.net_total * rate)

@property
def gross_total(self):
    return money(self.net_total + self.vat_amount)
```

**Important:** decide what you store:

* Either store computed totals on save (net/vat/gross) for audit/performance
* Or compute on demand.
  Recommended: **store line totals at creation/update**, and keep computed properties as a cross-check.

## 4) Store amounts (recommended for audit + speed)

### 4.1 Add stored totals to line items (recommended)

Add to `OrderItem` (and similarly `InvoiceItem` / `QuotationItem` if they exist):

* `net_total_amount Numeric(12,2)`
* `vat_amount Numeric(12,2)`
* `gross_total_amount Numeric(12,2)`

Then enforce recalculation on:

* item create
* item update (qty/unit/vat_rate)
* order finalize

Example method:

```python
def recalc(self):
    net = money(self.unit_price_dec * self.quantity_dec)
    vat = money(net * (Decimal(self.vat_rate) / Decimal("100")))
    gross = money(net + vat)
    self.net_total_amount = net
    self.vat_amount = vat
    self.gross_total_amount = gross
```

Then Order totals can sum these stored fields.

### 4.2 Why store?

* You can always reproduce totals at any time
* Faster reporting (no heavy recalculation)
* Better audit trail

## 5) Migration Plan (Flask-Migrate/Alembic)

### 5.1 Install & setup

1. Add dependency: `flask-migrate`
2. In `app.py`:

```python
from flask_migrate import Migrate
migrate = Migrate(app, db)
```

3. Remove `db.create_all()` from startup.

4. Initialize:

```bash
flask db init
flask db migrate -m "init migrations"
flask db upgrade
```

### 5.2 Convert float → Numeric

Migration steps:

* Add new Numeric columns alongside old float columns (safe path)
* Backfill using SQL cast/rounding
* Swap usage in code
* Drop old float columns later

Example approach for a column:

* Old: `price Float`
* New: `price_amount Numeric(12,2)`

Backfill:

```sql
UPDATE price_list SET price_amount = ROUND(price::numeric, 2);
```

Then update code to use `price_amount`.
Finally remove `price` after you confirm.

**Do this for:**

* PriceList.price
* Invoice.total_amount
* InvoiceItem.price
* any other float money fields

## 6) Security Changes

In `app.py`:

token = os.environ.get("API_TOKEN")
