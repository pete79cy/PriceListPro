You’re running into two separate UX gotchas:

1. **PDF download hijacks the current tab** (so you “lose” the quotations list context)
2. **Navigation has a real latency** (even if small), so taps feel “dead” for a moment

Here’s a clean, durable fix for both.

---

## 1) Fix “Download quotation” so it doesn’t trap you away from the list

### Best UX for a business app

* **Open the PDF in a new tab** (user can print/download)
* Keep the current quotation detail page intact
* Add an obvious **Back to quotations** button (and/or breadcrumb)

### A) Change the download link/button to open in a new tab

If your “Download quotation” is an `<a>` tag:

```html
<a
  href="/quotations/{{ quotation.id }}/pdf"
  target="_blank"
  rel="noopener"
  class="btn btn-primary"
>
  Download quotation (PDF)
</a>
```

If it’s a `<button>` that triggers navigation, change it to:

```html
<button
  type="button"
  class="btn btn-primary"
  onclick="window.open('/quotations/{{ quotation.id }}/pdf', '_blank', 'noopener')"
>
  Download quotation (PDF)
</button>
```

### B) Make the server return the PDF as “inline” (opens nicely in the new tab)

In Flask, when returning the PDF:

```python
from flask import make_response

@app.get("/quotations/<int:quotation_id>/pdf")
def quotation_pdf(quotation_id):
    pdf_bytes = build_pdf_for_quotation(quotation_id)  # your existing generator
    resp = make_response(pdf_bytes)
    resp.headers["Content-Type"] = "application/pdf"
    resp.headers["Content-Disposition"] = f'inline; filename="quotation-{quotation_id}.pdf"'
    return resp
```

> If you *force* `attachment`, the browser will always download (often still fine), but `inline` gives the “print / save” preview workflow people expect.

### C) Add a “Back to quotations” button on the quotation detail page

```html
<a href="/quotations" class="btn btn-secondary">
  ← Back to quotations
</a>
```

If you support filters/search on the list page, preserve them:

* best: use the HTTP `Referer` if present and sane
* simpler: include `?return=/quotations?...` when entering the detail page

## 2) Fix the “small delay” on navigation (make taps feel instant)

A loader helps, but only if it:

* shows **immediately** (same frame as the click)
* doesn’t appear for links that **open new tabs** (like the PDF link)
* doesn’t fight with normal browser behavior

### A) Loader JS (skip `_blank`, skip `download`)

```html
<script>
  function showNavLoader() {
    const el = document.getElementById("nav-loader");
    if (!el) return;
    el.classList.remove("hidden");
    // ensure paint happens immediately
    requestAnimationFrame(() => el.classList.add("visible"));
  }

  document.addEventListener("click", (e) => {
    const a = e.target.closest("a");
    if (!a) return;

    // ignore special links
    if (a.target === "_blank") return;
    if (a.hasAttribute("download")) return;
    if (a.dataset.noLoader === "1") return;
    if (!a.href || a.href.startsWith("javascript:")) return;

    // only same-origin navigations
    const url = new URL(a.href, window.location.href);
    if (url.origin !== window.location.origin) return;

    showNavLoader();
  });

  // cover form submits too
  document.addEventListener("submit", (e) => {
    showNavLoader();
  });

  // hide loader on bfcache restore
  window.addEventListener("pageshow", () => {
    const el = document.getElementById("nav-loader");
    if (!el) return;
    el.classList.add("hidden");
    el.classList.remove("visible");
  });
</script>
```

### B) Minimal loader HTML/CSS (fast + not annoying)

```html
<div id="nav-loader" class="nav-loader hidden" aria-live="polite">
  <div class="spinner"></div>
  <div>Loading…</div>
</div>

<style>
  .nav-loader {
    position: fixed;
    inset: 16px 16px auto auto;
    display: flex;
    gap: 10px;
    align-items: center;
    padding: 10px 12px;
    border-radius: 12px;
    background: rgba(0,0,0,0.75);
    color: white;
    opacity: 0;
    transform: translateY(-6px);
    transition: opacity 120ms ease, transform 120ms ease;
    z-index: 9999;
    pointer-events: none;
  }
  .nav-loader.visible {
    opacity: 1;
    transform: translateY(0);
  }
  .nav-loader.hidden {
    display: none;
  }
  .spinner {
    width: 14px;
    height: 14px;
    border: 2px solid rgba(255,255,255,0.35);
    border-top-color: rgba(255,255,255,1);
    border-radius: 50%;
    animation: spin 0.7s linear infinite;
  }
  @keyframes spin { to { transform: rotate(360deg); } }
</style>
```

### C) One extra “pro” trick: preload the next page

If the delay is server-side, you can still make it feel snappy by preloading on hover (desktop) or touchstart (mobile). Light-touch version:

```html
<link rel="prefetch" href="/quotations">
```

Or for key pages you hit constantly: `/quotations`, `/customers`, `/dashboard`.

---

## Net result

* Clicking **Download quotation** opens the PDF in a new tab → you’re never “stuck”
* The quotation detail page gains a **Back** action → zero confusion
* Navigation taps get **instant feedback** without messing with `_blank` links

Also: this is one of those tiny UX changes that makes the app feel “expensive” without actually costing you expensive engineering.
