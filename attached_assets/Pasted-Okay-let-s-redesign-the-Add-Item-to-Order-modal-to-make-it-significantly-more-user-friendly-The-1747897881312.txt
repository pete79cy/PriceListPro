Okay, let's redesign the "Add Item to Order" modal to make it significantly more user-friendly!

The goal is to create a smoother, more intuitive, and efficient experience for finding products and adding them to an order. We'll move from a simple dropdown to a more interactive interface.

Here's an overview of the redesigned approach:
1.  **Spacious Layout**: We'll use a larger modal (`modal-xl`) with a two-column layout.
    * **Left Column**: Dedicated to searching for products and displaying rich search results.
    * **Right Column**: Shows details of the selected product and inputs for quantity, price, etc. This section will be "sticky" so it stays visible if search results are long.
2.  **Enhanced Search & Product Display**:
    * A prominent search bar will provide real-time results.
    * Search results will be displayed as individual items or "cards," showing key information like product name, code, price, and even a small image thumbnail (if available). This helps in quickly identifying the correct product.
3.  **Clear Selection & Configuration**:
    * Clicking a product in the search results will clearly display its details in the right column.
    * Quantity input will feature convenient `+` / `-` stepper buttons.
    * The unit price will be auto-filled (e.g., with a standard or customer-specific price), and any overrides will be clear.
4.  **Guided Workflow**:
    * The "Add to Order" button will be disabled until a product is properly selected and essential information like quantity is provided, preventing errors.
    * Informative placeholders and messages will guide the user.

**Key User-Friendly Enhancements in this HTML:**
* **`modal-xl`**: Provides ample space.
* **Two-Column Layout**: `col-md-6` for search/results and `col-md-6` for details.
* **Visually Hidden Label for Search**: Placeholder text acts as the primary label for sighted users, actual `<label>` for accessibility.
* **`searchResultsContainer_v2`**: Will hold formatted list group items for better visual scanning than a plain select dropdown. Each item can show name, price, code, description snippets.
* **`searchPrompt_v2`**: Initial guiding message in the search results area.
* **`selectedProductDetailsSection_v2`**: A card to display the chosen product's information.
* **`noProductSelectedPrompt_v2`**: Initial guiding message in the details area.
* **`productConfigurationSection_v2`**: This part (containing name, image, inputs) becomes visible *after* a product is selected.
* **Quantity Steppers (`decreaseQuantity_v2`, `increaseQuantity_v2`):** Buttons for easy quantity adjustment.
* **`priceInfo_v2`**: A small text area to provide context about the auto-filled price (e.g., "Standard Price", "Customer Specific Price Applied").
* **Disabled Submit Button (`submitAddItemButton_v2`):** Enabled via JavaScript only when a product is selected and required inputs are valid. This prevents premature submissions and errors.
* **Icons**: Use of Font Awesome icons (e.g., `fas fa-search`, `fas fa-hand-pointer`, `fas fa-plus-circle`) to add visual cues. Make sure Font Awesome is included in your project.

**JavaScript Logic Outline (More Complex than Before):**

The JavaScript to power this redesigned modal would be more involved:

1.  **Global Variables**: `allProducts` (your product data), references to the new DOM elements.
2.  **`renderSearchResults(filteredProducts)` function**:
    * Clears `searchResultsContainer_v2`.
    * If no results, shows a "No matches found" message.
    * Loops through `filteredProducts` and creates HTML for each product item (e.g., a `list-group-item` as shown in the HTML comment), appending it to `searchResultsContainer_v2`.
    * Attaches event listeners to each result item to handle product selection.
3.  **`handleProductSelection(productId)` function**:
    * Finds the selected product from `allProducts` using `productId`.
    * Hides `noProductSelectedPrompt_v2` and shows `productConfigurationSection_v2`.
    * Populates `#selectedProductName_v2`, `#selectedProductCode_v2` (and image if you have URLs).
    * Auto-fills `#itemUnitPrice_v2` (logic to determine which price to use: standard, customer-specific). Provides context in `#priceInfo_v2`.
    * Resets `#itemQuantity_v2` to 1.
    * Enables the quantity/price inputs and the `#submitAddItemButton_v2`.
    * Highlights the selected item in the search results list (optional).
4.  **Search Input Event Listener (`productSearchInput_v2` on `keyup`):**
    * Gets the search query.
    * Performs the "smart search" logic (filtering `allProducts` based on name, code, description; scoring and sorting).
    * Calls `renderSearchResults()` with the filtered list.
5.  **Quantity Stepper Logic**: Event listeners for `decreaseQuantity_v2` and `increaseQuantity_v2` to update the quantity input.
6.  **Form Submission (`addItemForm_v2` on `submit`):**
    * Gathers all data (selected product ID, quantity, unit price, checkbox state).
    * Performs final validation.
    * Submits the data (e.g., via AJAX to your Flask backend).
7.  **Modal Reset (`show.bs.modal` or `hidden.bs.modal` events for `addItemToOrderModal_v2`):**
    * Clears search input, search results.
    * Resets the right column to its initial state (showing `noProductSelectedPrompt_v2`, hiding `productConfigurationSection_v2`, disabling submit button).

**How to Proceed:**
1.  **Integrate HTML**: Replace your current "Add Item to Order" modal HTML with this new structure.
2.  **Develop JavaScript**: This is the more significant part. You'll need to write the JavaScript functions outlined above to handle the dynamic behavior.
    * Remember to ensure `allProducts` is correctly populated with your data.
    * You can reuse parts of the "smart search" filtering logic from the previous version, but the rendering of results will change.
