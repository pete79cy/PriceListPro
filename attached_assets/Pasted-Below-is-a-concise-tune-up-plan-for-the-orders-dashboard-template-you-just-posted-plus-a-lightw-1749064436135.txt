## 2  Drop-in Vanilla JS for live search + customer filter

> Add this after jQuery (or adapt to your favourite framework).

```html
<script>
document.addEventListener('DOMContentLoaded', () => {
  const $search   = document.getElementById('orderSearchInput');
  const $customer = document.getElementById('customerFilter');
  const $rows     = [...document.querySelectorAll('#ordersTable tbody tr')];

  function normalise(txt) {
    return txt.toLowerCase().trim();
  }

  function filter() {
    const q        = normalise($search.value);
    const custId   = $customer.value;        // '' = All
    let visible    = 0;

    $rows.forEach(row => {
      const haystack   = normalise(row.innerText);
      const rowCustId  = row.dataset.customerId;
      const matchText  = q === '' || haystack.includes(q);
      const matchCust  = custId === '' || custId === rowCustId;
      const show       = matchText && matchCust;

      row.style.display = show ? '' : 'none';
      if (show) visible += 1;
    });

    // Optional: show “no results” row
    document.getElementById('noResults')?.classList.toggle('d-none', visible !== 0);
  }

  $search.addEventListener('input', filter);
  $customer.addEventListener('change', filter);
});
</script>
```

### Notes

* **Performance:** Even with a few thousand rows this is snappy; beyond that, consider DataTables or server-side pagination.
* **Accessibility:** Because the filter simply hides rows (instead of removing them), screen-reader focus remains predictable.
* **No external libs:** Works with or without jQuery.

## 3  Optional UX niceties

1. **Highlight hits** – wrap matches in `<mark>` so users see why a row matched.
2. **Persist filters in URL** – sync `search` & `customer` params via `history.pushState` so a refresh keeps the filter.
3. **Add CSV export** – once the table is filtered, let users download the visible rows with a single click (`tableexport.js` or your own small script).
