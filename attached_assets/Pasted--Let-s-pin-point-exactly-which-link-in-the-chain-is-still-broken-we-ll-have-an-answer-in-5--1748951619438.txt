## 1 ️⃣  Does the `filterProducts()` function ever fire?

Add one **single** log line inside `filterProducts`:

```js
async function filterProducts () {
  console.log('[DEBUG] filterProducts called');   // <-- add this
  …
}
```

*Open the modal, type* **l** **a** **n** **t** ►
*Do you see that message in **Console**?*

| Result              | Meaning                                                                             |
| ------------------- | ----------------------------------------------------------------------------------- |
| **No message**      | The listener never attaches → we’re still fighting a DOM-ready / modal-ready issue. |
| **Message appears** | The listener is fine – jump to step 2.                                              |

<details><summary>Quick repair if you get “no message”</summary>

Your modal is injected dynamically, so attach the listener when the
modal is shown (Bootstrap 5 syntax):

```js
document.addEventListener('shown.bs.modal', e => {
  if (e.target.id !== 'addItemModal') return;
  e.target.querySelector('#product_search')
          .addEventListener('input', filterProducts, { once: true });
  loadInitialProducts();
});
```

Remove **all** other `addEventListener('input', …)` lines for that element.
Now repeat the test.

</details>

## 2 ️⃣  Does the browser actually hit the API?

Keep DevTools **Network** panel open and type “lant”.

*Look for a request whose path ends in* `/products?...`.

| What you see                         | What it tells us                                                                                      |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| **No request at all**                | The code that issues `fetch` is throwing before the call (usually `resultsList` is null). See step 3. |
| **Request with 404**                 | Front-end path ↔ back-end blueprint mismatch.                                                         |
| **Request with 200 but empty array** | Search logic in Flask query returns no rows (SQL `ILIKE` maybe on wrong column).                      |
| **Request with 500**                 | Flask exception – check server logs.                                                                  |

**If you get 404:** your JS is hitting `/api/v1/products` but the route
is `/api/products` **or vice versa**.
Easiest fix:

```python
# blueprints/routes_api.py
api = Blueprint('api', __name__, url_prefix='/api/v1')   # 👈 make sure this line exists
```

(or change the fetch URL to `/api/products`).

## 3 ️⃣  If the fetch never fires, one DOM lookup is still null

Move the container **inside** the modal or delay the listener as in step 1.
